왼쪽 메뉴에서 원하는 화면으로 이동합니다. 좌측 상단의 광고주 선택 칸에서 담당 광고주를 고르면, 다음에 접속할 때도 자동으로 같은 광고주가 열립니다.

        

          
📊 전체 요약광고비·매출·ROAS 등 핵심 지표를 한눈에. AI가 전일 대비 변화를 코멘트로 요약해줍니다.

          
📋 리포트엑셀로 옮기기 좋은 표 형태 — 집계·필터·열 순서 변경·다운로드가 여기서 이뤄집니다.

          
📋 광고주 현황담당 광고주 전체의 마지막 수집 상태를 한 화면에서 확인합니다.

          
⚙️ 설정수집 기간·매체 선택, 데이터 수집 실행이 여기에 있습니다.

          
❓ 도움말지금 보고 있는 이 화면입니다.

          
💬 피드백문의·버그·기능 요청을 남기는 전체 공개 게시판입니다.

        

      


      

        
3. 신규 광고주 설정 순서

        
새 광고주를 처음 설정할 때는 아래 순서를 지켜주세요. 순서가 바뀌면 일부 데이터가 잘못 반영될 수 있습니다.

        

          

            
1

            

              
수집기간 입력 → 저장

              
설정 탭 상단 "📥 데이터 수집" 카드에서 날짜부터 먼저 정하고, 저장을 한 번 눌러둡니다.

            

          

          

            
2

            

              
매체별 수집항목 설정

              
어떤 매체를 사용할지, 어떤 지표를 리포트에 보여줄지 정합니다.

            

          

          

            
3

            

              
매체별 마크업 설정

              
마크업률·방식을 매체별로 지정합니다.

            

          

          

            
4

            

              
브랜드검색 계약 불러오기

              
네이버 브랜드검색을 쓰는 광고주라면, 관련 아코디언을 펼치는 순간 자동으로 계약을 불러옵니다. 자동으로 안 불러와지면 "네이버에서 계약 불러오기" 버튼을 직접 눌러주세요.

              
이후로는 네이버 수집을 실행할 때마다 시스템이 계약이 끝났는지·새로 생겼는지를 자동으로 다시 확인해 최신 상태를 유지해줍니다 — 이 단계는 사실상 처음 한 번만 신경 쓰면 됩니다.

            

          

          

            
5

            

              
저장

              
지금까지 설정한 내용을 저장합니다.

            

          

          

            
6

            

              
데이터 수집 실행

              
실제 매체 API를 호출해 데이터를 가져옵니다. 자세한 방법은 데이터 수집하기 참고.

            

          

          

            
7

            

              
리포트 값 표기 변환

              
수집된 실제 값을 확인한 뒤, 리포트에 필요한 이름으로 바꿉니다(예: 매체명을 납품용 명칭으로 변경).

            

          

          

            
8

            

              
네이버 GFA / 에이스카운터 리포트 업로드 (해당하는 경우만)

              
기기별 GFA 리포트나 에이스카운터 방문 로그 파일을 수동으로 올려야 하는 광고주는 이 단계에서 업로드합니다. 정규 수집이 끝난 뒤라야 매칭할 데이터가 있습니다.

            

          

          

            
9

            

              
마스터 시트만 다시 만들기

              
업로드 직후 자동으로 반영되긴 하지만, 확실히 하려면 한 번 더 눌러 확인합니다.

            

          

          

            
10

            

              
리포트 탭에서 열 순서 조정

              
리포트 탭으로 가서 상단 헤더를 실제 납품 양식 순서에 맞게 조정하고 양식을 저장합니다. 자세한 방법은 리포트 내려받기 참고.

            

          

        

        

          ⚠️
          
순서가 중요한 이유: "브랜드검색 계약 불러오기"는 그 시점에 저장되어 있는 수집기간을 기준으로 계약을 찾습니다. 날짜를 먼저 저장해두지 않으면 계약이 하나도 안 잡히거나, 이전에 다른 광고주를 설정할 때 남아있던 기간 기준으로 잘못 걸러질 수 있습니다.

        

      


      

        
4. 대시보드 보는 법

        
가장 자주 보게 될 화면은 전체 요약입니다.

        
핵심 지표 카드광고비·매출·ROAS를 큰 숫자로, 노출·클릭 등 보조 지표를 아래에 함께 보여줍니다.

        
⚙️ 지표 편집히어로·보조 지표와 차트에 어떤 지표를 보여줄지 직접 골라 구성합니다.

        
💡 추천 보기현재 데이터 특성을 바탕으로 AI가 지표 조합을 추천해줍니다. 자유 텍스트로 원하는 방향을 알려줄 수도 있습니다.

        
AI 코멘트코멘트 생성 버튼을 누르면 전일 대비 증감과 캠페인별 주요 변동을 자동으로 문장으로 정리해줍니다. 설정 탭에서 수집을 실행하면 자동으로도 생성됩니다.

        
기간 표시화면 상단 뱃지에 현재 표시 중인 수집 기간이 나타납니다.

        

          💡
          
같은 데이터를 다른 기준으로 재구성해서 보려면 리포트 탭의 집계(원본 · 매체 합산 · 캠페인 합산 · 그룹 합산)를 활용하세요.

        

      


      

        
5. 데이터 수집하기

        
새로운 기간의 광고 데이터를 직접 불러오고 싶을 때 사용합니다. 설정 탭 → 📥 데이터 수집 카드에서 진행합니다.

        

          

            
1

            

              
수집기간 설정

              
날짜를 직접 입력하거나, 어제 버튼(어제 하루) · 최근 7일 버튼(어제부터 7일)으로 빠르게 채울 수 있습니다.

            

          

          

            
2

            

              
이번에 불러올 매체 선택

              
기본값은 전체 선택입니다. 특정 매체만 다시 불러오고 싶다면 나머지 체크를 해제하면 됩니다 — 다른 매체의 기존 데이터는 그대로 유지됩니다.

            

          

          

            
3

            

              
수집 실행 클릭

              
완료되면 리포트에 자동으로 반영됩니다. 별도로 다시 계산할 필요가 없습니다.

            

          

        

        

          ⚠️
          
한 번에 최대 7일까지만 수집할 수 있습니다. 더 긴 기간이 필요하면 나눠서 여러 번 수집해주세요.

          
데이터가 많은 날은 수집이 한 번에 안 끝날 수 있는데, 수집 실행을 다시 눌러주면 이어서 처리됩니다.

          
네이버 수집 중 브랜드검색 계약이 새로 자동 감지되면 결과 화면에 ⚠️ 알림이 함께 뜹니다 — 광고비가 이미 반영된 것이니 내용만 확인해주세요.

        

        

          💡
          
📊 마스터 시트만 다시 만들기 버튼은 매체에 새로 접속하지 않고, 이미 불러온 데이터로만 리포트를 다시 계산합니다. 설정(수집 항목 등)만 바꾼 뒤 빠르게 반영하고 싶을 때 이 버튼을 쓰세요.

        

      


      

        
6. 리포트 내려받기

        
리포트 탭에서 원하는 형태로 표를 구성한 뒤 엑셀로 옮길 수 있습니다.

        

          
기간 필터상단 날짜 선택으로 원하는 기간만 볼 수 있습니다.

          
집계원본 · 매체 합산 · 캠페인 합산 · 그룹 합산 중 선택합니다.

          
필터특정 매체·카테고리 등 원하는 값만 골라서 볼 수 있습니다.

          
열 편집열 제목의 ⠿ 부분을 드래그해 순서를 바꾸고, ✕로 숨기고, + 열 추가로 필요한 열을 더할 수 있습니다.

          
⭐ 프리셋지금 구성한 기간·집계·필터·열 상태를 이름 붙여 여러 개 저장해두고, 필요할 때 골라서 바로 불러올 수 있습니다.

          
🧮 계산 컬럼기존 컬럼 두 개를 더하기·빼기·나누기·텍스트 결합으로 조합해 새 열을 만듭니다(예: 광고비÷전환DB=CPA, 기기+카테고리=모바일파워링크).

          
📊 매체 실제값과 비교매체 대시보드가 보여주는 실제 수치와 수집된 값을 나란히 대조해 오차를 확인합니다.

        

        

          

            
1

            

              
원하는 대로 표를 구성

              
기간·집계·필터·열 순서를 취향에 맞게 조정합니다.

            

          

          

            
2

            

              
💾 양식 저장 클릭

              
지금 만든 열 구성을 기억해두고 싶다면 눌러주세요. 본인 화면에만 적용되며 다른 담당자의 화면에는 영향을 주지 않습니다.

            

          

          

            
3

            

              
다운로드 또는 복사

              
⬇️ 엑셀 다운로드로 파일을 바로 받거나, 📋 복사로 클립보드에 담아 기존 엑셀 파일에 붙여넣을 수 있습니다.

💾 양식 저장을 눌러야 저장됩니다. 누르지 않고 창을 닫으면 다음 접속 시 초기화됩니다.

재발급 체크리스트 — 사람이 주기적으로 챙겨야 하는 것

        
실제로 사람이 손을 대야 하는 건 Meta 하나뿐입니다. 나머지는 자동 갱신되거나(GFA), 만료 개념 자체가 없거나(네이버SA·구글·GA4·카카오DA·카카오SA·Gemini), 매번 자동 재로그인됩니다(모비온).

        

          

            
매체사람이 할 일주기비고

            
              
Meta AdsAccess Token 재발급 후 설정 탭에 저장⚠️ 60일마다"광고주 현황" 탭 배너·설정 탭 배지로 만료 임박 시 자동 경고

              
네이버 검색광고(SA)없음-매 요청 서명(HMAC) 방식이라 만료 개념 자체가 없음

              
네이버 GFA없음-Access Token 401 발생 시 코드가 자동 갱신(Refresh Token 사용)

              
구글 Ads / GA4없음-Refresh Token 영구 발급(analytics.readonly 스코프 포함 필요)

              
카카오모먼트(DA)없음-비즈니스 토큰 영구 발급

              
카카오 키워드광고(SA)없음-비즈니스 토큰 영구 발급, REST API 키는 카카오DA와 공유

              
모비온없음-매 실행마다 코드가 자동으로 재로그인해 새 토큰을 받음

              
Gemini(AI 코멘트)없음-Google AI Studio 발급 키, 만료 개념 없음

              
에이스카운터해당없음-API 자체가 없어 수동 리포트 업로드 방식

            
          

        

      


      

        
저장 원칙

        

          💡
          
API 토큰·키 → 설정 시트에 고정(사람이 직접 보고 수정해야 해서 — 시트 잠금으로 보안 유지)

          
운영 설정(마크업률·매체별 KPI 토글·수집 스케줄 등) → Script Properties(코드가 관리, 시트 컬럼 추가 없이 유연하게 확장)

        

        
⚠️ Script Properties는 앱을 삭제하면 함께 사라지므로, 토큰처럼 복구 불가능한 값은 절대 여기에 저장하지 않습니다.

      


      

        
매체별 상세

        
계정/권한 요구사항, 설정 시트 저장 위치, 알아둘 점을 정리했습니다.


        

          ▶ Meta Ads
          

            
필요 계정Meta 광고 관리자 권한 + Marketing API 앱 접근권한(ads_management/ads_read 스코프)

            
저장 위치설정 시트 B17(Access Token)

            
만료·재발급⚠️ 60일마다 만료 — Meta 공식 "액세스 토큰 디버거"(developers.facebook.com/tools/debug/accesstoken/)에서 실제 발급/만료일 확인 가능

            
알아둘 점토큰을 재저장하면(값이 실제로 바뀔 때만) 아래 카운트다운이 자동으로 리셋됩니다. 광고비는 VAT 미포함 실비용이라 리포트에는 ×1.1 처리됩니다.

            

          

        


        

          ▶ 네이버 검색광고(SA)
          

            
필요 계정마스터 API 계정(전 광고주 공용) + 각 광고주 광고계정의 "회원 관리"에서 이 마스터 계정을 구성원으로 초대

            
저장 위치설정 시트 B2(API KEY)/B3(SECRET KEY), 광고주목록 D열(네이버ID, 복수계정은 콤마 구분)

            
만료·재발급없음 — 매 요청마다 HMAC 서명을 새로 만드는 방식이라 만료 개념 자체가 없음

            
알아둘 점다른 그룹(관리계정) 소속 광고주를 마스터 계정에 연동하려 하면 "관리계정 연동"/"광고계정 연동" 경로가 순환구조로 거부될 수 있음 — 이때는 "회원 관리" 탭에서 직접 구성원 초대로 우회. 최대 수집기간은 7일.

            

              🛠️
              
겪었던 문제 — 순환구조 거부가 나는 이유는 네이버 관리계정 구조가 관리계정→광고계정 계층을 최대 depth 5까지만 허용하고 순환 구조 자체를 금지하기 때문. 위 "회원 관리" 우회는 이 계층 제약을 아예 건너뛰는 방식이라 계층이 얼마나 깊어도 통함. 자세한 내용은 CHANGELOG_ARCHIVE.md 14-22절 참고.

            

          

        


        

          ▶ 네이버 GFA
          

            
필요 계정네이버 로그인 OAuth 2.0 앱(네이버 개발자센터) — 검색광고(SA)와는 별개 인증체계

            
저장 위치설정 시트 B19(Client ID)/B20(Client Secret)/B21(Access Token)/B22(Refresh Token)/B23(관리자 계정번호, 전역 기본값), 광고주목록 H열(GFAID)/L열(GFA관리자ID, 광고주별 오버라이드)

            
만료·재발급Access Token은 401 발생 시 코드가 자동으로 갱신 — 사람이 신경 쓸 필요 없음

            
알아둘 점이 매체만 호출마다 "AccessManagerAccountNo"(관리자 계정번호)를 함께 보내야 함 — 광고주가 다른 그룹(관리계정) 소속이면 전역 B23 대신 광고주목록 L열에 그 그룹 번호를 따로 입력해야 함(안 하면 403 FORBIDDEN). 기기(PC/모바일) 구분은 공개 API 미지원이라 수동 CSV 업로드로 보완.

          

        


        

          ▶ 구글 Ads
          

            
필요 계정Google Ads API Developer Token + MCC(전체 계정 통합관리) 하위에 각 광고주 계정 연결

            
저장 위치설정 시트 B7(Client ID)/B8(Client Secret)/B9(Refresh Token)/B10(Developer Token)/B11(MCC ID), 광고주목록 E열(구글ID, 복수계정 콤마 구분)

            
만료·재발급없음 — Refresh Token은 영구 발급(재인증 없이 계속 사용)

            
알아둘 점이 Refresh Token은 GA4에서도 그대로 재사용됨 — 최초 발급 시 analytics.readonly 스코프를 함께 요청해둬야 GA4 수집이 가능. API 버전은 v21 고정, 모든 요청에 login-customer-id(MCC ID) 헤더 필수.

          

        


        

          ▶ 카카오모먼트(DA)
          

            
필요 계정카카오디벨로퍼스 앱 + 비즈니스 인증 승인(카카오모먼트 광고계정 접근권한)

            
저장 위치설정 시트 B14(REST API KEY)/B15(비즈니스 토큰), 광고주목록 F열(카카오ID)

            
만료·재발급없음 — 비즈니스 토큰은 영구 발급

            
알아둘 점카카오 키워드광고(SA)와 완전히 별개 시스템(호스트 자체가 다름) — REST API 키는 공유하지만 비즈니스 토큰은 서로 다름. 보고서 API는 5초에 1회 호출 제한.

          

        


        

          ▶ 카카오 키워드광고(SA)
          

            
필요 계정카카오모먼트와 같은 앱을 재사용하되 "keyword_management" 동의항목 추가

            
저장 위치설정 시트 B32(비즈니스 토큰, REST API 키는 B14와 공유), 광고주목록 K열(카카오SA ID)

            
만료·재발급없음 — 비즈니스 토큰은 영구 발급

            
알아둘 점카카오모먼트(DA)와 달리 별도 심사 승인 절차가 필요 없음 — 앱 관리 화면에서 동의항목만 설정하면 바로 사용 가능. 광고비는 VAT 미포함 실비용이라 ×1.1 처리됩니다.

            

              🛠️
              
겪었던 문제 — OAuth 인가 시 resource_ids 파라미터를 생략하면 팀원이 매번 광고계정을 하나씩 수동으로 선택해야 함 — resource_ids=keyword:*로 요청하면 전체 광고계정 접근권한을 한 번에 부여받을 수 있음. 자세한 내용은 CHANGELOG_ARCHIVE.md 14-18절 참고.

            

          

        


        

          ▶ 모비온(Mobion)
          

            
필요 계정모비온 로그인 계정(대행사 통합계정 또는 광고주 전용 계정) — 담당자에게 별도 문의해 발급

            
저장 위치설정 시트 B34(아이디)/B35(비밀번호)/B36(Access Token, 자동 저장), 광고주목록 M열(모비온ID). 광고주별로 별도 로그인이 필요하면 관리자 화면에서 개별 override 등록 가능

            
만료·재발급없음 — 매 실행마다 코드가 아이디/비밀번호로 자동 재로그인해 새 토큰을 받음

            
알아둘 점모비온이 IP 화이트리스트를 요구해 AWS EC2 고정 IP(3.36.137.246) 프록시를 경유해 호출 중 — 신규 계정을 추가할 땐 이 고정 IP를 모비온 측에 화이트리스트 등록 요청해야 함. 광고비는 VAT 미포함이라 ×1.1 처리됩니다.

            

              🛠️
              
겪었던 문제 — 공식 API 문서 사이트 자체가 Postman 임베드 SPA라 크롤링이 안 돼, 공개된 자동화 신청 절차 없이 담당자와 직접 영업/계약 협의를 거쳐 "대행사 통합계정"을 발급받아야 했음. 자세한 내용은 CHANGELOG_ARCHIVE.md 14-26절 참고.

            

          

        


        

          ▶ Google Analytics 4(GA4)
          

            
필요 계정별도 전용 계정 없음 — 구글 Ads와 동일한 Refresh Token 재사용(analytics.readonly 스코프 포함 필요) + 해당 GA4 속성에 뷰어 권한

            
저장 위치광고주목록 I열(GA4 Property ID, 속성 2개 이상이면 콤마 구분)

            
만료·재발급없음 — 구글 Ads Refresh Token과 동일

            
알아둘 점Google Cloud Console에서 "Google Analytics Admin API"를 별도로 활성화해야 하는 경우가 있음(Data API와 다른 API 상품 — 안 켜져 있으면 403 오류) — 전환 이벤트명 드롭다운이 안 뜨면 이걸 먼저 확인.

          

        


        

          ▶ 에이스카운터
          

            
필요 계정해당없음

            
저장 위치해당없음 — 리포트 파일(CSV/엑셀)을 설정 탭에서 수동 업로드

            
만료·재발급해당없음

            
알아둘 점외부에서 통계를 꺼내오는 공개 API가 없어 사람이 직접 대시보드에서 파일을 받아 업로드하는 방식으로 처리 중 — 업로드 후 매체/카테고리/패턴 매칭 규칙을 등록해야 리포트에 정확히 반영됩니다.
